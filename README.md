# Octa Byte AI - DevOps Assignment

A complete reference implementation for the assignment using:

- AWS VPC with public/private subnets across 2 AZs
- Application Load Balancer
- Private EC2 instances running Docker
- RDS PostgreSQL in private subnets
- Amazon ECR
- AWS Secrets Manager
- IAM roles with least privilege
- Terraform remote-state bootstrap
- GitHub Actions CI/CD
- Staging -> manual production approval
- Trivy security scanning
- Prometheus + Grafana
- CloudWatch centralized logging
- RDS automated backups

## Architecture

```text
Internet
   |
   v
Public ALB
   |
   +----------------------+
   |                      |
   v                      v
Private EC2            Private EC2
Docker App             Docker App
   |                      |
   +----------+-----------+
              |
              v
       Private RDS PostgreSQL

GitHub Actions
   |
   +--> Tests
   +--> Trivy dependency/image scan
   +--> Build Docker image
   +--> Push ECR
   +--> Deploy staging through SSM
   +--> Integration test
   +--> Manual approval
   +--> Deploy production
```

## Prerequisites

- AWS account
- Terraform >= 1.6
- AWS CLI configured
- Docker
- Git
- GitHub repository
- GitHub OIDC IAM role

## 1. Bootstrap Terraform state

The bootstrap creates an encrypted/versioned S3 bucket for Terraform state.

```bash
cd terraform/bootstrap
terraform init
terraform apply
```

Copy the output values.

Then edit:

```text
terraform/backend.tf
```

and replace the placeholder bucket name.

## 2. Deploy infrastructure

```bash
cd terraform
terraform init
terraform fmt -recursive
terraform validate
terraform plan
terraform apply
```

Important: do not commit `terraform.tfvars` if it contains secrets.

Create it from:

```bash
cp terraform.tfvars.example terraform.tfvars
```

## 3. Build and run locally

```bash
cd app
docker build -t octabyte-devops-app .
docker run --rm -p 8000:8000 octabyte-devops-app
```

Test:

```bash
curl http://localhost:8000/health
curl http://localhost:8000/metrics
```

## 4. CI/CD

Configure GitHub Actions secrets/variables:

```text
AWS_ROLE_TO_ASSUME
AWS_REGION
ECR_REPOSITORY
STAGING_INSTANCE_ID
PRODUCTION_INSTANCE_IDS
```

Recommended GitHub Environments:

```text
staging
production
```

Protect the `production` environment with required reviewers. This creates the requested manual approval step.

The workflow:

```text
staging deployment via SSM

  v

  v
production deployment
```

## 5. Secrets

The PostgreSQL password is generated by Terraform and stored in Secrets Manager.

The application does not store credentials in Git.

The EC2 role can read only the application secret and pull from ECR.

## 6. Monitoring

The application exposes:

```text
/metrics
```

Prometheus scrapes the application.

Recommended Grafana dashboards:

1. Infrastructure
   - CPU
   - memory
   - disk
   - network
   - instance health

2. Application
   - requests/sec
   - request latency
   - 4xx
   - 5xx
   - application health

3. Database
   - CPU
   - connections
   - free storage
   - read/write latency

CloudWatch collects system/application logs.

## 7. Logging

CloudWatch log groups:

```text
/octabyte/application
/octabyte/system
/octabyte/access
```

Retention is configurable.

## 8. Security

- RDS is not publicly accessible.
- ALB is the only public application entry point.
- EC2 instances are private.
- Security groups restrict traffic by source security group.
- IAM uses roles instead of long-lived AWS access keys.
- Secrets Manager stores database credentials.
- ECR images are scanned.
- Trivy scans dependencies and the final container.
- S3 state is encrypted and versioned.
- RDS storage is encrypted.
- Production deployment requires manual approval.

## 9. Cost optimization

For a demo/staging environment:

- use small EC2 instances
- use a small RDS instance
- keep log retention limited
- destroy the stack when the assignment is complete:

```bash
terraform destroy
```

NAT gateways and RDS are among the main recurring costs.

## 10. Challenges / resolutions

Example items to document after implementation:

- Private EC2 instances need NAT access for package/ECR operations.
- GitHub Actions should use OIDC instead of static AWS keys.
- RDS must remain private.
- ALB health checks need a lightweight `/health` endpoint.
- Deployment to private instances is handled with SSM instead of exposing SSH.
